# MaiJur G1 Native UI Implementation Plan

> **For Codex:** Execute this plan task-by-task with `superpowers:subagent-driven-development`. Use a fresh `gpt-5.6-sol` high implementer and a fresh `gpt-5.6-luna` max reviewer for every task. Do not push to GitHub.

**Goal:** Deliver the complete iPhone-first MaiJur UI with deterministic in-memory mock data so Journals CRUD and History presentation can be evaluated before persistence or Foundation Models are introduced.

**Architecture:** `MaijurApp` owns one concrete Observation-based `MockJournalStore`. `ContentView` exposes exactly two native tabs, each with its own `NavigationStack`. Feature views render store state and invoke store mutations; the editor owns only a temporary `JournalDraft`. No repository protocols, persistence layer, model sessions, network, or custom design system are added in G1.

**Tech Stack:** Swift 6, SwiftUI, Observation, Swift Testing, XCTest UI testing, Xcode 26.5, iPhone 17 Simulator (iOS 26.5).

## Settled design decisions

- Use exactly two root tabs: **Journals** and **History**.
- Push journal/history details in their tab's `NavigationStack`; present the journal editor in a sheet with its own `NavigationStack`.
- Start the runtime with populated deterministic mock data; represent empty, loading-like, and unavailable-insight states through deterministic fixtures and previews.
- Loading-like states are static presentation states. Do not add timers, fake networking, or async model work.
- Journal deletion does not delete mock History snapshots. History remains read-only and preserves source journal dates.
- Use native `List`, `Section`, `ContentUnavailableView`, `ProgressView`, `TextEditor`, `DatePicker`, toolbars, confirmation dialogs, system typography, and system colors.
- Avoid fixed text heights, custom fonts, gradients, cards, spacing-token systems, and speculative shared components.
